# 🚪 TCP SYN Flood Attack Investigation

This project explains how a **TCP SYN Flood attack** works and demonstrates how to investigate the attack using **Wireshark and a PCAP file**.

The investigation focuses on identifying suspicious SYN traffic, understanding the TCP handshake, analyzing source and destination IPs, checking incomplete connections, and determining whether IP spoofing or a distributed attack may be involved.

---

# 📖 1. What is a TCP SYN Flood?

## Simple Definition

A **TCP SYN Flood** is a **Denial-of-Service (DoS) attack** that abuses the TCP connection establishment process.

The attacker sends a large number of TCP `SYN` packets to a server but does not complete the TCP 3-way handshake.

When the server receives a SYN, it prepares and maintains information about the connection in a **half-open state** while waiting for the final `ACK`.

If too many half-open connections are created, the server's **SYN backlog or other connection resources can become exhausted**.

As a result, legitimate users may experience slow connections, connection failures, or timeouts.

---

# 🔄 2. How Does the TCP 3-Way Handshake Work?

A normal TCP connection uses three steps:

```text
Client                         Server

   SYN  ------------------------>

        <------------------  SYN/ACK

   ACK  ------------------------>

         Connection Established

### 1. SYN
The client sends a SYN packet to request a TCP connection.

### 2. SYN/ACK
The server receives the SYN and responds with SYN/ACK.
The server keeps information about this connection while waiting for the client's final ACK.
This is called a half-open connection.

### 3. ACK
The client sends the final ACK.
The connection is now established.

---

## 💥 3. What Happens During a SYN Flood?

During a SYN Flood, the attacker repeatedly sends SYN packets:

```text
Attacker                         Server

   SYN  ------------------------>
   SYN  ------------------------>
   SYN  ------------------------>
   SYN  ------------------------>
   SYN  ------------------------>
   SYN  ------------------------>
                ...
```

The server processes these connection requests and maintains many half-open connections.
The attacker does not complete the handshake.

```text
SYN → SYN/ACK → No ACK
SYN → SYN/ACK → No ACK
SYN → SYN/ACK → No ACK
SYN → SYN/ACK → No ACK
              ...
              ↓
      Many half-open connections
              ↓
   SYN backlog/resources consumed
              ↓
 Legitimate connections may be affected
```
#### 🏢 The Flipkart Example
Suppose the Flipkart Big Billion Days sale is live. An attacker tries to send many `SYN` packets to the Flipkart server. 

The Flipkart server stores these half-open connections in its memory. Soon, the server's memory becomes completely exhausted. 

When legitimate users want to access the website to buy something, they get an error saying the server is unreachable.

## 💥 4. DoS vs DDoS

A SYN Flood is an attack technique. It can be used as either a DoS or DDoS attack.

### DoS — Denial of Service
A DoS attack attempts to make a service unavailable using a non-distributed attack source.

```text
Attacker
    |
    | Many SYN packets
    v
Victim Server
```

#### Example:
```text
10.10.10.50  ── SYN ──> 10.10.10.100
10.10.10.50  ── SYN ──> 10.10.10.100
10.10.10.50  ── SYN ──> 10.10.10.100
```
One source is generating the attack traffic.

### DDoS — Distributed Denial of Service
A DDoS attack is a DoS attack generated by many genuine and distributed systems.

```text
Machine 1 ──┐
Machine 2 ──┤
Machine 3 ──┼──> Victim Server
Machine 4 ──┤
Machine 5 ──┘
```

For example, an attacker may control a botnet containing thousands of compromised systems. All of these systems can send traffic toward the same target.

> ⚠️ **Important:** Multiple source IP addresses alone do not prove DDoS. The IP addresses could be spoofed. We need additional evidence to determine whether the traffic actually originated from multiple machines.

---

## 🎭 5. What is IP Spoofing?

### Simple Definition
IP spoofing means changing the source IP address in a packet so that the packet appears to come from another system.

For example, an attacker may actually be using:
`10.10.10.50`

but send packets claiming to come from:
`192.168.1.10`
`192.168.1.20`
`192.168.1.30`

The victim may therefore see many different source IP addresses.

```text
                 SYN
One attacker ───────────> Victim
              Source IP: 10.1.1.1

                 SYN
One attacker ───────────> Victim
              Source IP: 10.1.1.2

                 SYN
One attacker ───────────> Victim
              Source IP: 10.1.1.3
```

### Relationship Between the Attacks
*   **SYN Flood + One genuine source** $\rightarrow$ DoS
*   **SYN Flood + Many genuine sources** $\rightarrow$ DDoS
*   **SYN Flood + Spoofed source IPs** $\rightarrow$ Spoofed SYN Flood

### 🕵️‍♂️ Important Forensic Point
Multiple source IP addresses can make a single-source attack look like a distributed attack.

If multiple source IPs are associated with the same source MAC address in a local Layer-2 capture, this can support the hypothesis that the IP addresses are being spoofed.

However, a MAC address is not absolute proof of one attacker in every PCAP. If traffic has passed through a router, the original source MAC may not be visible.
